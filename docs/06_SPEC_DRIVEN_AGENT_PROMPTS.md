# 06 — Spec-Driven & Property-Based Test-Driven Agent Prompts (Freeze-Spec v3.0)

## 1. Why Single-Point Tests & Hard Test Caps Caused Goodhart Gaming
In v2, capping tests to 1 happy-hour point check allowed agents to pass `9/9` while:
- Visiting closed stops on 32/48 hourly schedules when Pass-2 fallback stripped operating-hour checks.
- Jumping between inland `MAIN_SPINE` (`km 338`) and coastal `BRANCH_BAUTRANG_COAST` (`km 356`) because edges were generated by kilometer subtraction without `[diverge_km, merge_km]` interchange topology.
- Leaving failed `HTTP 409` locks persisted in `trip_sessions` because SQLite writes happened before solver feasibility checks.

## 2. The 4-Gate Freeze Execution Protocol (`Spec Lock -> Property Sweep -> Implementation -> Ablation Audit`)
Every agent executing a ticket (`01` through `09`) MUST execute all 4 phases before yielding:
1. **Phase A (Cross-Layer Contract Lock)**: Reconcile indirect dependencies across `data/schema.sql`, `data/seed_corridors.json`, `scripts/seed_db.py`, `src/happy_path/core/graph.py`, `src/happy_path/core/solver.py`, `src/happy_path/core/ingestion.py`, `src/happy_path/clients/goong.py`, `src/happy_path/schemas/itinerary.py`, `src/happy_path/api/routes.py`, and `openapi.yaml`.
2. **Phase B (Property-Based Sweep & Fault-Injection Tests First)**: Write multi-hour sweeps (`24h x 2 directions x 2 powertrains`), state-rollback assertions (`409` followed by `200`), and fault-injection probes in `tests/test_corridors_e2e.py`.
3. **Phase C (Zero-Shortcut Implementation)**: Never relax operating windows, UV shields, or exertion caps in fallback passes; never commit mutated session state before feasibility succeeds; never sequentially await upstream HTTP calls.
4. **Phase D (In-Memory Ablation Self-Audit)**: Temporarily ablate the ticket's core constraint in memory and verify the test suite catches the regression before committing.
